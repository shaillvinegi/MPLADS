1. RESEARCH OBJECTIVE & EXPERIMENT SCOPE
--------------------------------------------------------------------------------
This research experiment investigates the empirical behavior of the Isolation Forest
anomaly detection algorithm across three varying train-test split configurations:
  - Experiment 1: 60% Training Data, 40% Testing Data
  - Experiment 2: 75% Training Data, 25% Testing Data
  - Experiment 3: 80% Training Data, 20% Testing Data

The objective is to analyze whether varying the sample ratio impacts the stability,
execution time, anomaly score distributions, and relative anomaly detection proportions
when holding all hyperparameter configurations constant.

2. EXPERIMENTAL CONSTANTS & REPRODUCIBILITY
--------------------------------------------------------------------------------
The following parameters and setup were held strictly constant across all splits:
  - Algorithm: Isolation Forest (scikit-learn)
  - Contamination Rate: 0.05 (5.0% expected anomaly proportion)
  - Number of Estimators: 100 trees (identical to production monitoring pipeline)
  - Random State: 42 (reproducible seed)
  - Parallel Jobs: -1 (all available CPU threads)
  - Total Dataset Size: 41,086 historical MPLADS project records
  - Preprocessing Approach: Null values imputed to 0.0, infinite values bounded.
  - Fit/Transform Discipline: Transformations fit on training partitions to prevent leakage.

3. FEATURE SET UTILIZED
--------------------------------------------------------------------------------
The 7 quantitative project-monitoring features engineered in Nirakshan-AI were used:
  1. sanction_amount
  2. total_disbursed
  3. budget_disbursement_ratio
  4. sanction_lead_time_days
  5. payment_tranche_count
  6. max_single_tranche_ratio
  7. work_description_length

6. COMPARATIVE ANALYSIS & PPT PRESENTATION HIGHLIGHTS
--------------------------------------------------------------------------------
A. Anomaly Count vs Anomaly Percentage:
   - Absolute anomaly counts decrease as the test set becomes smaller:
     * 60:40: 808 anomalies (16,435 test records)
     * 75:25: 525 anomalies (10,272 test records)
     * 80:20: 419 anomalies (8,218 test records)
   - However, the PERCENTAGE of flagged test records remains remarkably consistent
     at ~4.8% to 5.0%, perfectly matching the configured contamination parameter (5.0%).
   - Scientific Takeaway: Comparing raw anomaly counts across different splits is misleading
     because sample sizes differ; normalized percentage provides the scientifically valid metric.

B. Training vs Prediction Scalability:
   - Training time scales proportionally with training set size.
   - Prediction time scales proportionally with test set size.
   - Total pipeline execution remains fast (< 1.5 seconds) across all configurations,
     demonstrating excellent computational feasibility for offline monitoring batches.

C. Anomaly Score Distribution Stability:
   - The score distributions show very stable central tendencies (mean ~0.08 to ~0.09).
   - Standard deviations remain narrow (~0.056 to ~0.058), confirming that tree isolation
     partitioning is robust to changes in the training fraction.

7. RESEARCH INTEGRITY & METHODOLOGICAL LIMITATIONS
--------------------------------------------------------------------------------
1. Unsupervised Nature: Isolation Forest isolates observations without ground-truth labels.
   Records flagged with label -1 represent statistical outliers in the 7-dimensional feature
   space. They indicate unusual disbursement patterns, delayed approvals, or tranche anomalies,
   NOT verified evidence of corruption, fraud, or contractor misconduct.
2. No Supervised Metrics: Because reliable ground-truth audit labels for fraudulent projects
   are not present in public government datasets, supervised metrics (Precision, Recall, F1)
   cannot be reported without fabricating ground-truth labels. We strictly avoid fabrication.
3. Production Separation: This experiment is an offline research benchmark. The live Nirakshan-AI
   platform, dashboards, REST endpoints, and existing models were kept completely unaltered.
